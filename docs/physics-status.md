# 物理モデルの現状

この repo のデモは **`Mode::Kinematic`** で動く。重力・移流・壁クランプだけを行う決定的なモデルで、圧力の連成は解かない。MPS 法の完全な semi-implicit ステップは `Params::mps()` / `Mode::Mps` に実装してあるが、**静止した水柱で圧力が立たない**問題が残っており、実験的な扱いである。

## 動いているもの

- 粒子配置（決定的、ジッターなし）
- 参照数密度 `n0` の初期配置からの実測
- `re/r - 1` カーネルと数密度（近傍リスト経由と直接総和の一致はテスト済み）
- 一様グリッド・Verlet リスト（ブルートフォースとの完全一致をテスト）
- CSR 疎行列と active マスク付き Jacobi-CG（小さな SPD 系で既知解と一致、特異系で NaN を出さないことをテスト）
- CFL 時間刻み、型付きステータス（`Ok` / `TimestepTooSmall` / `Diverged`）
- 明示粘性（標準 MPS ラプラシアン）

## 残っている問題

`Mode::Mps` では静止水柱が重力で沈み、圧力が 0 のまま床で圧縮される。原因の切り分けは次の段階まで進んでいる。

- 右辺は非ゼロ（初期配置で `n*` が床側 23.3、天井側 42.5、`n0` 34.3、`rho0/dt²/n0` を掛けて 10⁷ オーダー）。
- 行列は組めている（880 行、23k 非ゼロ、対角は負の大きな値）。
- CG の前処理が `diag > 0` を仮定していて負の対角に対して退化していた問題を修正した（`diag.abs()` を使用）。
- ICP の各パスで対角を作り直すよう修正した（pinned 行に古い係数が残らないように）。
- それでも `cg=0`（反復 0 回で収束判定）となり、`pmin = pmax = 0`。

疑わしい点、次に確認すること:

1. `active` マスクと `rhs` の対応（`rhs[0] != 0` の一方で `masked_norm(b, active)` が 0 になっていないか）。
2. `mul_active` の列マスク（`active[j]` が false の列を落とす処理）が `SparseMatrix` の行と一致しているか。
3. 圧力増分の解ではなく、`p0 + p1` の分割（`docs/` 内で試作した `p0_i = -(rho0/dt²)(n*-n0)/lambda_i`）との整合。
4. 自由表面の境界条件（壁を Dirichlet 0 として扱う現在の方式）が静止水柱で正の圧力を出すか。

## デモとの関係

デモ（native / ブラウザ）は `Mode::Kinematic` を固定して使っている。したがって:

- native と wasm-gc の `FRAME` 行は 1 バイトも違わない（`tools/smoke.sh`）。
- ブラウザの表示は「粒子が重力で落下し、床で止まる」ところまでで、**ダムブレイクの波面や静水圧が正しく出るのは圧力ソルバが直ってから**。

`Mode::Mps` を直したら、`host/native` と `host/browser` のパラメータを `Params::mps()` に切り替えるだけで、同じ `FRAME` 契約のままデモが MPS になる。
